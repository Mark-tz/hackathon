# 阿里云部署指南

## 架构总览

```
参赛者浏览器
   │ HTTPS (443)
   ▼
┌──────────┐  反向代理   ┌──────────────────┐
│  Nginx   │ ──────────▶ │  Flask 127.0.0.1  │  ← oj-server.service
│  443/80  │             │  :8088            │
└──────────┘             └──────────────────┘
                                │
                                │ SQLite (WAL)
                                ▼
                        ┌──────────────┐
                        │  评测 worker  │  ← oj-worker.service
                        │  (子进程隔离) │
                        └──────────────┘
```

两个 systemd 服务跑在低权限用户 `oj` 下；Nginx 负责 TLS 终止与反代。
Flask 默认只监听 `127.0.0.1`，不要在安全组开放 8088。

---

## 准备工作

### 购买云服务器（ECS）

推荐规格：
- 1 核 2GB 或 2 核 2GB（突发型 t5/t6 即可，月费约 30-60 元）
- 系统镜像：Ubuntu 22.04 LTS
- 安全组开放端口：**22**（SSH）、**80**、**443**，不开 8088

### 域名 DNS

在域名服务商处添加 A 记录：

```
hackathon.turing-zero.com  →  <你的公网IP>
```

## 二、推送代码到 ECS（rsync）

由于 ECS 无法访问 GitHub，直接从本机同步：

```bash
# 在本机仓库根目录运行（替换用户名/主机/目标路径）
rsync -rltvO --no-owner --no-group --no-perms \
  --exclude '.git' \
  --exclude 'oj/oj.db*' \
  --exclude 'oj/uploads' \
  --exclude 'oj/viz' \
  --exclude 'oj/worker.lock' \
  --exclude '__pycache__' \
  ./ turingzero@<ECS_HOST>:./hackathon/
```

参数说明：不同步属主、属组和权限（`--no-owner --no-group --no-perms`），也不设置目录时间（`-O`）。
setup.sh 会把 `oj/` 改为 `root:oj`；如果用 `rsync -a`，它会尝试改回属组，报 `chgrp ... Operation not permitted`。

之后每次更新代码，重跑这条 rsync，再执行 `sudo systemctl restart oj-server oj-worker`。
只有 service 文件有改动时，才需要重跑 `sudo bash deploy/setup.sh`。

## 三、一键部署

```bash
# 在 ECS 上
cd /home/turingzero/hackathon

# 1. 运行部署脚本（创建 oj 用户、装依赖、注册 systemd 服务、初始化数据库）
sudo bash deploy/setup.sh

# 2. 设置管理员密钥（必改）
sudo nano /etc/oj.env
#   将 OJ_ADMIN= 后面替换为随机字符串：
#   OJ_ADMIN=$(openssl rand -hex 24)

# 3. 启动服务
sudo systemctl start oj-server oj-worker

# 4. 生成演示榜单数据（部署后运行一次）
sudo -u oj python3 tools/seed_demo.py
```

`setup.sh` 完成的工作：
- 安装 `python3 python3-pip git flask`
- 创建系统用户 `oj`（无家目录、无登录 shell）
- `oj/` 目录设为 `root:oj 775`，`oj/oj.db`、`oj/uploads`、`oj/viz` 归 `oj:oj`（SQLite WAL 模式需要目录可写）
- 拷贝 `deploy/oj.env.example` → `/etc/oj.env`（权限 640，root:oj）
- 安装并 enable `oj-server.service` / `oj-worker.service`（路径从脚本位置自动推导）
- 以 `oj` 用户初始化数据库

## 四、配置 Nginx 反向代理 + HTTPS

### 4.1 安装 Nginx 和 certbot

```bash
sudo apt-get install -y nginx certbot python3-certbot-nginx
```

### 4.2 部署站点配置

```bash
cd /home/turingzero/hackathon
sudo cp deploy/nginx-hackathon.conf /etc/nginx/sites-available/hackathon
sudo ln -sf /etc/nginx/sites-available/hackathon /etc/nginx/sites-enabled/hackathon
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

### 4.3 申请 Let's Encrypt 证书

```bash
sudo mkdir -p /var/www/certbot
sudo certbot --nginx -d hackathon.turing-zero.com \
    --non-interactive --agree-tos -m you@example.com --redirect
sudo nginx -t && sudo systemctl reload nginx
```

### 4.4 验证

```bash
curl -I https://hackathon.turing-zero.com/
```

浏览器访问 `https://hackathon.turing-zero.com` 看到 OJ 前端。

## 五、管理后台

访问 `https://hackathon.turing-zero.com/admin`，输入 `/etc/oj.env` 中的 `OJ_ADMIN` 密钥：

- **队伍管理**：创建队伍、查看 token、删除队伍
- **提交记录**：查看所有提交状态、分数、错误信息；对失败提交点"重试"

无需手动分发 token——通过管理页面创建队伍后，token 直接显示在浏览器中可复制。

## 六、日常运维

```bash
# 查看状态
sudo systemctl status oj-server oj-worker

# 实时日志
sudo journalctl -u oj-server -f
sudo journalctl -u oj-worker -f

# 重启
sudo systemctl restart oj-server oj-worker

# 阶段切换（A → B）
sudo sed -i 's/^OJ_PHASE=.*/OJ_PHASE=B/' /etc/oj.env
sudo systemctl restart oj-server

# 添加队伍（也可通过 /admin 页面操作）
REPO=/home/turingzero/hackathon
sudo -u oj python3 ${REPO}/oj/db.py addteam "队伍名称"

# 备份数据库
sudo cp ${REPO}/oj/oj.db ${REPO}/oj/oj.db.bak
```

## 七、安全清单

| 项 | 状态 | 说明 |
|----|------|------|
| Flask 只监听 127.0.0.1 | ✅ | `OJ_BIND=127.0.0.1`（默认），nginx 反代 |
| 低权限用户 `oj` | ✅ | 无登录 shell，无家目录 |
| systemd 沙箱 | ✅ | `ProtectSystem=strict` `ProtectHome` `PrivateTmp` `NoNewPrivileges` |
| 评测子进程隔离 | ✅ | `RLIMIT_CPU/AS/FSIZE/NOFILE` + 敏感环境变量清除 |
| 单 worker 串行 | ✅ | flock 防止并行，节省内存 |
| HTTPS 强制跳转 | ✅ | nginx 80 → 443 301 |
| 管理密钥 | ⚠️ 手动 | `/etc/oj.env` 的 `OJ_ADMIN` 必须改成随机串 |
| 安全组 | ⚠️ 手动 | 阿里云控制台只放行 22/80/443，不开 8088 |

管理员密钥生成：

```bash
openssl rand -hex 24
```

## 附：手动部署（不用 setup.sh）

```bash
# 1. 装依赖
apt update && apt install -y python3 python3-pip nginx
pip3 install flask

# 2. 建低权限用户
useradd -r -s /sbin/nologin -d /nonexistent -M oj

# 3. 设置权限（REPO 改成实际路径）
REPO=/home/turingzero/hackathon
mkdir -p ${REPO}/oj/uploads ${REPO}/oj/viz ${REPO}/oj/demo_viz
chown -R root:root ${REPO}
chown root:oj ${REPO}/oj && chmod 775 ${REPO}/oj
chown -R oj:oj ${REPO}/oj/uploads ${REPO}/oj/viz ${REPO}/oj/demo_viz
touch ${REPO}/oj/oj.db && chown oj:oj ${REPO}/oj/oj.db && chmod 660 ${REPO}/oj/oj.db

# 4. 初始化数据库
sudo -u oj python3 ${REPO}/oj/db.py init

# 5. 配环境变量
cp ${REPO}/deploy/oj.env.example /etc/oj.env
chown root:oj /etc/oj.env && chmod 640 /etc/oj.env
# 编辑 OJ_ADMIN...

# 6. 安装 systemd 服务（替换路径）
sed "s|/home/hackerson|${REPO}|g" ${REPO}/deploy/oj-server.service > /etc/systemd/system/oj-server.service
sed "s|/home/hackerson|${REPO}|g" ${REPO}/deploy/oj-worker.service > /etc/systemd/system/oj-worker.service
systemctl daemon-reload
systemctl enable oj-server oj-worker
systemctl start oj-server oj-worker

# 7. 装 nginx（见第四节）
# 8. 生成演示数据
sudo -u oj python3 ${REPO}/tools/seed_demo.py
```

## 故障排查

**服务起不来：**
```bash
sudo journalctl -u oj-server -n 50 --no-pager
```
常见原因：`/etc/oj.env` 权限不对（应为 root:oj 640）、`oj/` 目录权限不对（应为 root:oj 775）。

**数据库 readonly 错误：**
```bash
ls -la /path/to/hackathon/oj/
# oj/ 目录需要 drwxrwxr-x root oj
# oj.db 需要 -rw-rw---- oj oj
sudo chown root:oj /path/to/hackathon/oj && sudo chmod 775 /path/to/hackathon/oj
sudo chown oj:oj /path/to/hackathon/oj/oj.db && sudo chmod 660 /path/to/hackathon/oj/oj.db
```

**评测卡住/超时：**
```bash
sudo journalctl -u oj-worker -n 50 --no-pager
```

**nginx 502：**
Flask 没起来，检查 `systemctl status oj-server`；确认 `/etc/oj.env` 的 `OJ_PORT` 与 nginx `proxy_pass` 端口一致（8088），且 `OJ_BIND` 为 127.0.0.1。

**证书续期：**
```bash
sudo certbot renew --dry-run
```
