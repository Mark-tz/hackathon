# 备选题 B：设备异常下的生产恢复调度

> 选手版题面草案 V0.1 · 通用规则见 `00_参赛须知_通用规则.md` · 文中数值为示例

---

## 1. 背景

设备停机是车间里最常见的意外。停机之后，是等它修好，还是把任务转到备用机上？备用机速度慢，切换还要换型。有些设备在故障前会有征兆，要不要提前做预防性维护？

你的任务是：**在固定的生产窗口内，面对设备的异常和故障，协调机械臂搬运和设备分配，让窗口内合格产出尽可能多。**

---

## 2. 系统

| 要素 | 规格（公开范围） |
|---|---|
| 机械臂 | 1 台，单夹爪 |
| 主力设备 | 2–3 台，加工快 |
| 备用设备 | 1–2 台，兼容全部或部分工序，速度慢 10%–60%，首次使用前需要换型 |
| 工件 | 1–2 类，每类 2–3 道工序，原料**充足**（窗口内不会做完） |
| 缓冲区 | 容量 0–3 |
| 生产窗口 | 每个实例公布 `window_ms`，到时结束，统计进入成品区的合格件数 |

---

## 3. 故障与维护机制

| 编号 | 机制 | 规则 |
|---|---|---|
| R1 | 故障 | 发生时刻和持续时间都是**预先生成**的，与你的行为无关，所有队伍面对同样的故障。恢复时刻要等恢复时才知道 |
| R2 | 加工中故障 | 正在加工的这道工序作废。工件留在机床上，设备恢复后可以卸下重做这道工序。工件不会被销毁 |
| R3 | 健康信号 | 每台设备都有 `vibration`（振动）读数，故障前一段时间可能上升。**预警的提前量和可靠性因场景族而异**（有的族误报很多） |
| R4 | 预防性维护 | 动作 `pm`：设备停机 `pm_ms` 毫秒。如果它在未来 `pm_window` 内本来要发生故障，这次故障被**取消**，但取消的是什么事件，选手看不到。PM 的代价和效果参数公开 |
| R5 | 返工 | 设备恢复后的前 k 件，有概率 `p_defect` 出现不合格，需要回到上一道工序返工 |
| R6 | 换型 | 把备用机切换到另一种工序或工件类型，需要换型时间，期间占用备用机 |

> 关于 R4 的公平性：故障表预先生成并封存。PM 只能取消表中已有的事件，不会产生新的随机事件，所以所有队伍面对的外生序列是相同的。

---

## 4. 目标

- **主指标**：窗口结束时进入成品区的合格件数 Q，越多越好。单局得分按产出类缺口闭合率计算（`base` 为 0 分，`ref` 为 100 分）。
- 本局判为无效的情况：非法动作、工件守恒被破坏、超时或崩溃。
- 只用于解释、不参与计分：故障后第一件产出的时间、换型次数、PM 次数及命中率、设备利用率。

## 6. 场景族

| 族 | 公开特征 |
|---|---|
| R1 短故障 | 故障频繁但很短，转移任务往往不划算 |
| R2 长故障 | 故障少但很长，备用机是关键 |
| R3 连续故障 | 多台设备先后故障，备用机产能紧张 |
| R4 高换型 | 备用机换型代价高 |
| R5 可靠预警 | 振动信号的提前量充足、误报少，PM 收益高 |
| R6 嘈杂预警 | 误报多，盲目做 PM 会亏 |
| R7 返工 | 恢复后的不合格率高 |
| H1–H2 | 隐藏族，参数在公开范围内，机制组合是新的 |

规模：开发集每族 10 例；公开榜每族 2 例；正式集每族 5 例 × 3 种子。

---

## 7. 阶段 B ECR 范围预告

不超过下列 2 类：

- **设备**，例如增加一台可移动备用机，或者把备用机改为多工位。
- **维护**，例如维修人员有限，同一时间只能修一台。
- **目标函数**，例如改为合格件数减去在制品惩罚，或者按工件类型赋权。
- **信息**，例如增加新的健康信号，或者健康信号会延迟到达。

协议框架、动作给出方式和计分公式的形式不变。

---

## 8. 参考基线

| 策略 | 说明 |
|---|---|
| `baseline_ref` | 故障后保持原来的分配，等设备恢复；从不做 PM，也不主动启用备用机。**定义 0 分**（实例生成时保证基线产出大于 0） |
| `ref` | 已知全部故障时刻后离线求解的结果（可以完美安排 PM），**定义 100 分** |

本题考查的是调度恢复。振动信号是合成数据，成绩**不代表**真实的故障诊断能力或剩余寿命预测能力。
